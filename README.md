# FB Marketplace 智能卖家助手

一个 Manifest V3 的 Chrome 浏览器插件,面向在 Facebook Marketplace 上卖东西的
个人卖家:

1. **导入你已有的商品** —— 一键扫描你 Facebook 上「正在出售」的商品列表,把每条
   商品的标题、价格、类别、成色、描述、图片都读进插件里,不需要再手动重新输入
   一遍。
2. **一键重新上架 / 到期自动重新上架** —— 对导入或手动添加的任意一条商品,点
   「立即重新上架」就会把它的完整信息(标题/价格/类别/成色/描述/图片)原样发一
   个新的出去;也可以设置「到期后自动重新上架」按固定天数自动重复这个动作,保持
   商品排名靠前。可选(默认关闭)在重新上架成功后自动删除 Facebook 上的旧版本。
3. **自动回复(询盘机器人)** —— 监听 Marketplace 收件箱里的新消息,按你设置的
   关键词话术自动回答(还在吗 / 最低多少 / 在哪取货 / 怎么付款等),并把取货地址
   和购买方式一并告诉买家;规则库没命中时,可以选择让 AI(用你自己的 Anthropic
   API Key)结合商品信息智能生成回复。

## ⚠️ 先看这个:两类真实风险

**1) 你的 Facebook 账号可能被限制。** Facebook 用户协议禁止自动化 / 机器人行为。
本插件只在你自己已登录的账号上操作,不做验证码绕过、不伪造设备指纹,但频繁自动
发布、批量重新上架、或者让「自动回复」全速运行,仍然可能被 Facebook 的风控系统
盯上,导致账号或商品被限制、下架甚至封禁。**默认设置都偏保守**(自动填表但不
自动点发布、自动回复默认「试运行」不真发消息),建议你按需要一步步放开,而不是
一上来就全自动跑满。

**2) 如果打算在 Chrome 网上应用店公开上架,这类插件有被下架的风险。** Google 并
没有一条规则直接写「禁止自动化 Facebook 的插件」,但 Chrome 网上应用店的政策禁止
「滥用/垃圾信息行为」,而且历史上不少自动发帖 / 自动私信类插件在被平台(这里是
Meta)投诉后遭到下架或强制下线。也就是说:**审核当下可能通过,但不代表长期稳
定**。如果你只是自己用,不追求「上架给别人装」,可以完全跳过网上应用店,只用
「开发者模式加载已解压的扩展程序」的方式使用,没有这个风险。如果你确实要公开
发布(哪怕只是给自己的客户/团队用),请把下面的要求和风险都看完再决定。

## 上架 Chrome 网上应用店需要准备什么

1. **开发者账号**:去 <https://chrome.google.com/webstore/devconsole> 注册,一次性
   缴纳 $5 注册费。
2. **打包与代码要求**:
   - 必须是 Manifest V3(本项目已经是)。
   - 不能有「远程托管代码」——所有会执行的 JS 都必须打包在插件里,不能从你自己
     的服务器动态下载脚本来执行(插件里调用 Anthropic API 只是普通的网络请求、
     返回文本,不算执行远程代码,允许)。
   - 权限要「最小必要」:本项目的 `host_permissions` 只申请了
     `facebook.com` 和(可选功能用到的)`api.anthropic.com`,没有申请
     `<all_urls>`,提交时更容易通过「权限理由」审核。
3. **商店素材**:
   - 图标:128×128 PNG(必需),建议再准备 48×48、16×16。
   - 商店小图:440×280 PNG/JPG(必需)。
   - 至少 1 张截图,建议 1280×800 或 640×400。
   - 简短描述(≤132 字符)+ 详细描述 + 分类 + 语言。
4. **隐私政策**:因为插件会读取/操作 `facebook.com` 页面内容、并且可选功能会
   把消息发给 Anthropic API,提交时必须在开发者后台的「隐私权规范」(Privacy
   practices)标签页里如实填写收集了哪些数据类型,并提供一个**可公开访问的隐私
   政策链接**。本项目已经附带 `PRIVACY_POLICY.md` 模板,发布前把里面的占位内容
   换成你自己的信息,并挂到一个公开可访问的地址(比如 GitHub Pages、自己的网站)
   上,再把链接填进开发者后台。
5. **单一用途说明**:Chrome 网上应用店要求插件「用途单一、对用户清晰可见」。本
   项目的自动发布 + 到期重发 + 自动回复,都是围绕「帮 Marketplace 卖家管理商品
   和买家咨询」这一个用途,建议在商店描述里明确写清楚这一点。
6. **如实描述功能,不要用「涨粉」「刷单」「无限制自动化」这类夸张措辞** ——审核和
   之后的用户举报都会以你商店页面上的描述作为参照。

如果只是自己用,以上这些都可以跳过,直接用「开发者模式 → 加载已解压的扩展程序」
安装即可,不需要上架。

## 安装方法(开发者模式加载)

1. 下载 / 克隆本仓库到本地。
2. 打开 Chrome,访问 `chrome://extensions`。
3. 打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」,选择本项目所在文件夹。
5. 安装完成后,点击工具栏里的插件图标打开面板。

## 使用方法

### 1. 导入你已有的商品

**这一步现在是对着你「当前正在看的那个标签页」直接操作,不会再自己乱开/乱跳
标签页。**

1. 在浏览器里打开你自己 Facebook 的「Marketplace → 我的商品 / 正在出售」页面,
   **保持它是你当前正在看的这个标签页**(不要切走)。
2. 点插件图标打开面板。面板顶部「从当前页面导入商品」会显示当前标签页的网址:
   - 如果显示 ⚠️ 说明当前标签页不是 Marketplace 页面,先切过去再重新打开插件面板。
   - 如果插件是刚装上或刚更新的,而这个 Facebook 标签页是更早之前就开着的,第一
     次扫描可能会报"连接失败"——**刷新一下这个 Facebook 标签页**,再重新点扫描
     就行(刷新后插件脚本才会真正注入到页面里)。
3. 点「扫描当前页面」。插件会直接读取你当前这个页面上显示的商品卡片(过程中
   页面会自动上下滚动一下,把还没加载出来的商品也加载出来,这是正常现象,不是
   出 bug 了)。扫描出来的商品会列成一个带勾选框的清单,标题+价格+缩略图。
4. 勾选你要导入的商品(默认全选),点「导入选中的商品」。这一步会依次打开每件
   商品自己的编辑页,把标题/价格/类别/成色/描述/图片都读出来存进插件——**这一步
   会在后台依次打开几个标签页**,数量越多耗时越长,面板上会显示「导入进度:
   3 / 8」这样的实时进度,不用去管那些后台标签页,等进度显示"完成"就好了。
5. 导入完成后,这些商品会显示「已从 Facebook 导入(未在队列中)」——**导入本身
   不会发布或修改 Facebook 上的任何东西**,只是把信息读进插件,完全只读安全。

### 2. 一键重新上架 / 到期自动重新上架

1. 对导入好的(或手动添加的)任意一条商品,点「立即重新上架」,插件会用这条商品
   保存的完整信息(标题/价格/类别/成色/描述/图片)去发一个新的 listing。
   - **类别 / 成色文字需要和 Facebook 页面上显示的选项完全一致**(中文账号写
     「电子产品」「二手 - 良好」,英文账号写 `Electronics`、`Used - Good`);
     如果是从 Facebook 导入的,这两项理论上会跟你原来选的一致,但建议第一次用
     的时候还是打开「编辑」核对一下。
2. 想让它自动定期重新上架,就在编辑这条商品时勾选「到期后自动重新上架」,设置
   间隔天数(不建议小于 3–7 天,间隔太短更容易被 Facebook 判定为异常)。
3. **关于自动删除旧版本(默认关闭,请谨慎开启)**:重新上架本质是「新发一个」,
   Facebook 上原来那条不会自动消失。如果你想让插件在确认新的发布成功后,自动去
   把旧的那条删掉,需要同时打开两个开关——「发布设置」里的总开关,加上这条商品
   编辑页里的「重新上架成功后自动删除旧版本」——两个都开才会真正执行删除。这是
   **不可撤销**的操作,建议先只用「新发一个、旧的自己手动删」这种更安全的方式,
   跑顺了、确认插件工作正常之后再考虑开启自动删除。
4. 在「发布设置」里可以设置两次发布的间隔秒数,以及是否「自动点击发布」(不勾
   选则只自动填表,停在发布前一步,由你手动确认发布,更安全)。

### 3. 自动回复买家咨询

1. 在「商家信息」里填写取货地址和购买/付款方式——这两项会被自动回复引用。
2. 在「常见问题话术」里维护关键词 → 回答的规则(内置了几条常见问题的默认话术,
   可以直接编辑或删除),回答里可以用 `{{title}}` `{{price}}` `{{condition}}`
   `{{description}}` `{{address}}` `{{purchase}}` 这些变量。
3. （可选)如果想让规则库没命中的问题也能被智能回答,在「自动回复」设置里开启
   「AI 智能回复」,填入你自己的 Anthropic API Key。这一步**只影响规则库没匹配
   到关键词的消息**,并且明确要求 AI 只根据你提供的真实商品信息作答,不会编造
   「库存紧张」「限时优惠」这类不存在的营销话术。
4. 打开 Facebook 的 Marketplace 收件箱(或消息)页面并保持标签页存在,插件会在
   后台监听这个页面里的新消息。**默认是「试运行」模式**——只会把「收到什么 /
   会怎么回复」写进面板下方的日志,不会真的发送。建议先观察一段时间,确认识别
   没有问题(尤其是有没有把买家自己的消息误判、有没有对旧消息重复回复)后,再
   到设置里关闭试运行,让它真正发送。
5. 如果你自己在某个对话里手动回复了(不是插件生成的那句话),插件会认为这个对话
   已经「转人工」,之后不会再对这个对话自动回复,除非你重新打开自动回复。

## 文件结构

- `manifest.json` — 插件配置(Manifest V3)
- `background.js` — 后台队列调度(`chrome.alarms` 控制发布/重新上架/导入的间隔)+
  调用 Anthropic API 生成 AI 回复
- `field-utils.js` — 多个内容脚本共用的 DOM 辅助方法(找输入框、找按钮、读写字段值)
- `content.js` — 注入到 Facebook 商品**发布**页面,自动找到表单并填写
- `content-my-listings.js` — 注入到「我的商品/正在出售」管理页面,扫描现有商品列表
- `content-item.js` — 注入到单个商品页面,负责读取详情(导入用)和删除旧商品
- `content-inbox.js` — 注入到 Facebook 收件箱/消息页面,监听新消息并自动回复
- `storage.js` — 本地存储(`chrome.storage.local`)的公共读写方法,商品模板 /
  设置 / FAQ / 自动回复状态都在这里
- `popup.html` / `popup.js` / `popup.css` — 插件弹出面板界面
- `PRIVACY_POLICY.md` — 上架 Chrome 网上应用店时需要的隐私政策模板

## 关于「为什么不能一次做到完美识别」

这个插件读取 Facebook 页面的方式,是在代码里按常见的 HTML 写法(`aria-label`、
`role="article"` 之类)去找元素,不是 Facebook 官方提供的数据接口。开发这个插件
的过程中**没有办法登录你的 Facebook 账号去实际验证选择器对不对**(也不会问你要
账号密码——这个坑绝对不能开),所以这些选择器本质上是「有根据的猜测」,遇到你
账号/地区的具体页面版本,猜不准是完全可能发生的,不是"不智能",是缺一个"拿真实
页面反馈回来对一下"的环节。

为了把这个环节补上,现在做了两件事:

1. **每个查找步骤都准备了不止一种识别方式**(比如找"类别"字段会依次尝试
   `aria-label`、关联的 `<label>`、`<select>` 下拉框、`role="combobox"` 弹层
   按钮四种写法;找商品列表的滚动容器时,会自己判断是整个网页在滚、还是页面里
   有一个单独的内层容器在滚,分别处理),尽量覆盖 Facebook 常见的几种实现方式。
2. **失败时会自动收集诊断信息**(页面网址、找到了多少个商品链接、页面上有哪些
   按钮的文字等,不含你商品的具体内容)。扫描如果读不到东西,面板上会出现
   「复制诊断信息」按钮,点一下复制,把这段内容发给开发者,就能针对你账号的
   真实页面结构精确修选择器,而不是继续两眼一抹黑地猜。这是目前这类插件唯一
   靠谱的"越用越准"的方式。

## 已知限制 / 需要你自己核实的地方

- 只处理商品类目的发布流程(`/marketplace/create/item`),车辆、房屋租售等其他
  类目页面结构不同,尚未适配。
- **导入功能依赖的三个页面结构(管理页列表、单品编辑页、单品删除按钮)都是启发式
  匹配**,是整个项目里最容易因 Facebook 改版而失效的部分之一。如果扫描不到商品、
  或者导入回来的类目/成色是空的,用上面说的「复制诊断信息」反馈,比自己去改
  `content-my-listings.js` / `content-item.js` 里的选择器更可靠。
- `content-inbox.js` 靠「按文字/aria-label 匹配」来判断消息是买家发的还是你自己
  发的、找到聊天输入框——这也是容易因 Facebook 改版而失效的部分,出问题时请打开
  浏览器控制台(F12)看插件的日志。这也是为什么默认开着「试运行」。
- **自动删除旧商品**(`content-item.js` 里的 `DELETE_ITEM`)是不可逆操作,默认
  需要两层开关都打开才会执行,并且把确认按钮的查找范围限制在弹窗内,但仍然建议
  先跑一段时间「只发新的、不删旧的」,确认没问题后再考虑打开。
- 图片通过 `DataTransfer` 注入到文件选择框实现,单张图片建议不要太大。
- 不包含任何验证码 / 短信验证 / 人机验证的绕过逻辑,弹出验证时需要你手动完成。
- AI 智能回复需要联网调用 Anthropic API,会产生你自己账号下的 API 费用(用的是
  `claude-haiku-4-5`,单次回复成本很低,但仍建议留意用量)。
